For overlapping copy/unload tests, record that the copy was actually pending before the newer copy or unload; a triggered controlled delay may supply that boundary, but sequential copies or an armed-only delay do not prove cancellation.

For a deterministic HTML-copy await boundary, open that marked fixture in Source mode and let it settle. Place the caret in A, run the provider's **Arm one HTML copy renderer gate**, then the product's **Copy current table as HTML**. Wait for the persistent **caught/holding A after the real renderer completed** notice; it means the real renderer succeeded and its result is held before the product can continue. While held, separately test a newer real B copy, product disable through host UI with the provider left enabled, and an ordinary source edit without another copy. Use **Release HTML copy renderer gate** after the intervening action. Check actual clipboard output, product notices and source independently: B stays latest; unloaded A stays silent and a new instance copies B; ordinary editing retains the command's original A snapshot. Rearm for each case. Keep the visible caught signal, action order and `_html-copy-gate-observations.json`; this bounded diagnostic record issues no verdict. An early background catch, armed-only state, renderer error, Disarm or timeout cannot pass. Arm expires after two minutes and capture after five minutes. The provider wraps only the public renderer for one exact fixture cell and never writes the clipboard or calls product internals; it is a fixture resource, absent from production assets. This verifies an injected await boundary, not natural rendering latency or a retraction of an already dispatched system write. Record mobile TSV separately from desktop rich HTML.
