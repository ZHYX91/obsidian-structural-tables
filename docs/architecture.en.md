# Structural Tables — Architecture

<!-- section: boundaries -->
## Boundaries

`src/core` is host-independent pure TypeScript. Configuration, rendering, editor, Reading view, and app wiring are layered. The public repository depends on no adjacent repository or local Vault.

<!-- section: parser -->
## Parser

The parser scans GFM delimiter candidates whose cells contain one or more hyphens, skips BOM-prefixed frontmatter closed by either `---` or `...`, fenced code, and indented code, respects escaped pipes and code spans, and emits source ranges, role grids, merge anchors, and diagnostics.

Row/column reorder is a pure axis permutation shared by menu movement and drag/drop. It rejects partial span selections and role changes before validating the resulting owner grid. Insertion and an active cell draft compose into one candidate source and one host transaction. The DOM drag controller owns only selection gestures, measured boundaries, feedback and cancellation; source validation and writing remain in the shared operation path.

<!-- section: validation -->
## Validation

Merges resolve only to the previous source column or upward, preventing directional cycles regardless of display direction. Validation then checks anchors, role boundaries, and rectangular closure. Strict row width applies after structural mode is active.

<!-- section: rendering -->
## Rendering

One shared DOM renderer serves the Reading view postprocessor and CodeMirror presentation widget. Live Preview stores a semantic block widget plus an independent source-suppression decoration in a CodeMirror `StateField`, while a separate view plugin owns composition, native-source focus and view lifecycle. The Markdown range remains authoritative in the CodeMirror document; the suppression decoration only controls its visual/native rendering and is not the semantic table itself. Structural tables always enter this path; ordinary GFM tables enter it only while the opt-in takeover setting is enabled. Refreshing that setting rebuilds editor decorations and Reading views without changing source. Each visible anchor cell carries block-end and inline-end flags derived from its row/column span, so CSS removes internal borders by grid geometry rather than DOM-child position. Row backgrounds sit below transparent data cells so zebra stripes can continue under row spans. The owned widget adds cell selection, row/column handles, a roving tab stop for each control group, and a focused textarea editor. Visual cell focus maps to the corresponding Markdown anchor and synchronizes the logical CodeMirror selection while explicitly retaining presentation ownership; **Edit table source** reverses that ownership, reveals the raw lines, scrolls to the mapped cell, and focuses CodeMirror. Mouse pointers own drag selection; touch pointers use a two-tap range state and deliberately preserve the host's initial pointer event for scrolling and long press. Reading view parses Obsidian's complete section text with its Markdown container and protected-region context intact, including fenced/indented code, frontmatter, comments, display math, and literal raw HTML blocks started by `pre`, `script`, `style`, or `textarea`. It filters parsed tables to the exact reported source-line range and only then maps either an Obsidian-native table or the exact raw source block emitted for row-header syntax; this prevents protected examples from being acquired and a later table from being substituted with an earlier one. Recursive renderer callbacks are ignored. Cell content uses Obsidian MarkdownRenderer, with component lifecycle cleanup.

Live Preview separates immutable CodeMirror widget descriptions from DOM-owned interaction sessions. Source-editing ownership is independent from browser focus: opening external controls retains the raw source and its selection. Visual-cell actions explicitly yield that ownership while synchronizing a logical cursor. A source-position or table-index change rebinds an unchanged table to the current snapshot without recreating its textarea or dropping a draft. Parsed tables are cached in editor state until the document changes; selection, settings, and composition changes only rebuild decorations. Cell traversal belongs to the pure core and visits visible anchors in source order in both directions, skipping covered merge slots.

Single-line prose edits may map cached table ranges only when neither the old nor new line can change block ownership. HTML delimiters and paragraph-ending syntax invalidate the cache; successive-edit tests compare the resulting table models with a complete parse. Native table menu writes use the same complete-document boundary validation as owned-table actions.

Each owned table host publishes one versioned source snapshot: `data-structural-source-version="1"`, `data-structural-source-from`, `data-structural-source-to`, `data-structural-source-path`, and `data-structural-source`. The offsets are UTF-16 positions in the editor document; the exact source includes container prefixes and excludes the final line terminator and any separate following block-ID line. Cooperating plugins must validate the complete snapshot against the current file, range and source text before resolving a supported target. Missing, stale or ambiguous identity must not fall back to table indexes. Mounting and rebinding update the fields synchronously; identical tables have different ranges, and unchanged source text is stored only once per table host without being reassigned on unrelated updates.

Reading replacements, standalone-export staging and native comparisons create their root directly through the target's `ownerDocument`; Live Preview comparisons use the editor's document. Adopting a root created in another window changes its document but retains its original DOM prototype, which can make host helpers create descendants with the wrong window's constructors. Plugin-owned table nodes inherit the target root's helpers. Native Markdown content remains host-owned and may retain different constructors after insertion, so matching does not require every native descendant to share the plugin's realm.


Standalone Markdown renderers without section metadata use a separate source-verified adapter. It reads the saved note, compares complete native-rendered blocks (including ordinary tables to reject ambiguous literal markers), rechecks source identity and lifecycle, and awaits semantic cell rendering before returning. It never guesses table identity from DOM position or mutates Markdown. Failed, stale, partial or ambiguous matches remain native.

Native Callout blocks use a source-owned mounting session rather than reverse DOM offsets or unchecked table indexes. The editor resolves the source block with CodeMirror's forward position mapping; both views compare native-rendered block signatures, including rich raw paragraphs and multi-block headers. Identical tables use source order only when the complete matching target inventory agrees. Embedded-note targets and ambiguous mappings stay untouched. Editor mounts track changes by source range and exact source, and pending cell focus is fulfilled only when the matching replacement mounts. Host mutations retry pending mappings; diagnostics distinguish missing DOM, rendering, failed rendering, unmatched or ambiguous targets, and mounted tables.

When an eligible Callout has no native container, a visible exact source-line match can request a source-owned fallback shell. Only blocks containing valid owned tables qualify; protected HTML/code and unowned ordinary tables cannot request it. The shell renders the complete quote through the native Markdown renderer and reuses the same verified table mounting session. Source selection reveals the complete original quote; leaving source restores presentation, and double-clicking the fallback title enters source. Asynchronous stale or failed renders preserve source and release their components. Normal native containers retain their existing path.

Callout writes carry invertible focus targets in CodeMirror's own history, isolated from adjacent prose edits. Undo and redo restore the exact source/path target after remounting, including commands invoked outside a cell. Unrecorded source changes map those targets through the host history; no parallel undo stack is maintained.

Interrupted dirty editors hand their text to an application-session recovery buffer before DOM disposal. Its dialog supports copying and explicit discard; dismissing the dialog keeps the buffer available through a command. Recovery never automatically writes a stale draft to a new table.

Reading View also maps a simple merged table when the host leaves its exact raw lines in a paragraph. Acquisition requires a unique complete-line range, unchanged source/section/DOM identity and no intersecting media or widgets. A containing inline HTML span retains its node identity and attributes; ambiguous text and protected HTML remain untouched.

The interaction responsibilities are split into `cell-draft-session` (raw value, selection and draft-local history), `table-focus-session` (ownership and pending focus across remounts), and `range-clipboard-session` (frozen selections and asynchronous clipboard checks). These modules do not dispatch document changes. The widget and captured command target retain the validated commit boundary.

<!-- section: editing -->
## Editing

Commands and in-place edits produce candidate source from a pure in-memory ownership grid and parse it again. Row/column transformations rebuild rectangular merge ownership and migrate surviving anchors. Guarded operations refuse invalid boundaries plus unintended loss of unselected or hidden content; explicit clear/remove intents may discard only the user-selected visible owners. Cell input escapes unescaped pipes outside code spans before one whole-table CodeMirror transaction. Every explicit source write aligns separator pipes by terminal display width, including CJK and emoji, while preserving row-header dividers, alignment markers, escaped pipes, Wiki links, code spans, and the note's existing LF, CRLF, or CR line ending. Rendering never calls the serializer or writes source.

A synchronous edit captures the exact original document string in a `TableDocumentSnapshot` and parses that original only once. Target revalidation and neighboring-table checks share this snapshot. Validation still parses the complete result document, checks the intended result and every neighbor, and rechecks the editor's exact source before dispatch. Snapshots are operation-local; they are never reused after an asynchronous gap or a changed document.

<!-- section: interchange -->
## Interchange

Plain GFM conversion has a pure plan for each available orientation. It reuses the existing transpose and portable projection without writing the intermediate table. A row-header-only table recommends transpose; keep-orientation remains available. Plan metadata explains repeated merged cells, collapsed header levels, lost row-header roles, added empty headers, alignment resets and hidden overflow. The modal renders the final GFM through the Markdown renderer with recursive acquisition suppressed; the source pane and clipboard use the same candidate. Editor targets share the transpose command's captured file/view/CodeMirror identity and complete-document boundary guard, then dispatch one history-isolated replacement. Reading targets have no write callback and re-read saved source before opening or copying. Modal generations discard stale asynchronous renders, and plugin unload closes every preview.

A pure-core projection expands a valid structural table into stable column paths and two-dimensional data. GFM, TSV, CSV, and later record migrations share that projection; semantic HTML uses the validated rowspan, colspan, roles, scope, and real break elements. Whole-note HTML-import wiring normalizes an HTML DOM into cells, spans, th/td roles, and canonical `<br>` visual breaks before the pure core generates and reparses structural Markdown. Sheets Extended migration accepts only one non-edge pseudo-separator column whose cells are all exact `-` tokens.

Owned grid ranges use a separate normalized v1 payload with relative canonical owner IDs and raw owner tokens. Paste into a rectangular selection requires equal dimensions and owner topology. An unchanged single-cell anchor can expand the destination to fit the copied rectangle; partial merges, changed drafts and invalid role boundaries are refused. Both paths construct and validate one complete candidate and apply a single source transaction. Menu clipboard writes and reads check platform support independently. Unsupported payloads, ordinary text, and HTML never fall through from an owned-grid selection to hidden source. Portable range HTML represents spans with escaped raw text; plain Markdown treats the first copied row as a header and retains structural markers where representable, without guaranteeing merge topology in external GFM.

Whole-table PNG export has its own desktop session. It renders the validated model with the normal semantic renderer in an offscreen shell retaining source cssclass and Callout scopes, waits for cell rendering, the public `finishRenderMath()` barrier, fonts and images, measures complete content, and converts a styled DOM clone through pinned MIT-licensed `html-to-image` SVG foreignObject and canvas. Loaded image attachments are rasterized locally; required SVG symbols, active CSS resources including pseudo-elements, and successfully selected font sources are embedded. Font rules are associated with their specific CSS-connected FontFace by normalized descriptors and document order, distinguishing Unicode subsets, widths and repeated descriptors with different sources; inactive rules are excluded. Font collection follows source priority, retains the note's existing font fallback and never mutates host stylesheets. Resource validation parses attributes and declarations rather than text. The theme guard observes actual source presentation and theme mode, allowing unrelated renderer head updates and render-child replacements in the same verified note. It does not reuse the intentionally simplified Word/HTML projection. Cancellation, render errors, source/theme changes, excessive dimensions/nodes/resources and unsupported dynamic embeds refuse the result. A final PNG Blob supplies preview, clipboard and Vault attachment saving; a repeated request cancels its predecessor, and modal close or plugin unload releases the render component, offscreen DOM, event subscriptions and object URL. No source write or upload occurs.

<!-- section: base-promotion -->
## Base promotion

The pure core derives stable unique property keys, record values, filename candidates, list-valued `structural-tables` membership, and embedded Base source from the shared table projection. A new promotion preserves every trimmed non-empty column path as its Property key, reserves `column_n` for wholly blank headers, resolves canonical duplicates and control-key collisions with numeric suffixes, and emits YAML-quoted `note.<key>` property IDs for display configuration. Filters use bracket access in expressions. The metadata reader parses YAML and accepts both property IDs and older expression-shaped orders without rewriting notes. Column-header merges flatten into column paths, and merged row-header values repeat per record; data-region merges must be split first. The app layer allocates a unique table directory and ID per promotion, creates every record plus `_promotion.json`, reparses the unchanged source table, and then performs one editor replacement. Records have no plugin identity property. A creation, snapshot or editor failure retains all generated output and reports the directory path with the original error. The Vault API cannot atomically compare file contents and trash a directory, so failure handling performs no automatic cleanup.

Versioned `structural-tables` YAML configuration stores the table ID and manifest path through native Base saves. Legacy metadata comments remain readable. An unmarked Base is only a recovery candidate when one mandatory membership identifies a unique block; before any write, its original manifest must match the source note, table ID and recorded manifest path. A moved unmarked source cannot be inferred safely and requires explicit metadata repair. Duplicate IDs, conflicting metadata, malformed YAML and unsafe paths are refused. The offline YAML parser is pinned and bundled for browser use.

The recovery manifest records the original table, generated Base, source file, and initial record paths. Restoration replaces only the current plugin Base with the matching ID and never deletes records. Membership does not query paths, so record rename and move need no event listener. The plugin's new-record command computes an inbox from the host note's current folder; moving the host never moves existing records. Runtime reads both `structural-tables` and legacy `structural_table_ids`; equivalent dual values are accepted, while malformed or conflicting values fail closed. The explicit Vault-wide migration previews each affected file and action, keeps optional cleanup counts synchronized with the toggle, rechecks plugin-owned frontmatter and exact Base blocks, updates old membership fields and Base filters across LF, CRLF, and CR endings, and offers off-by-default `structural_record_id` cleanup only for notes with valid membership. Fence-aware discovery ignores examples nested in longer Markdown fences. If a later write fails, rollback reverses only the properties and exact blocks written by the migration, preserving unrelated concurrent edits.

Base services, Base previews and formatting previews belong to one loaded plugin instance. Unload permanently disposes the services, closes their previews and prevents old commands from starting another write or opening a note. A write already dispatched may finish; later steps stop and retain partial output. Legacy-property migration binds the original registered file and path, checks related open editor buffers, and revalidates them inside the atomic source callback. It patches only the owned YAML fields and Base blocks, preserving unrelated source bytes. Owned keys with anchors, tags or explicit-key syntax are refused before writing because a local deletion could change neighboring fields or aliases. Compensation also checks identity and buffers and is not started after unload. PNG export has the same permanent service lifetime, while a completed image remains a stable snapshot for the lifetime of its open preview.

<!-- section: settings -->

## Settings

Persisted settings use a schema-1 envelope. The previous unversioned object is the only legacy input: startup sanitizes it once and queues the schema-1 envelope, while current schema-1 data is normalized without another migration. Any explicit unknown or malformed schema is incompatible and read-only, so this plugin version cannot overwrite future fields. Settings saves pass through one serialized coordinator. Each queued save owns an immutable snapshot, failed saves remain visible and retryable, and unload flushes the queue and retries the latest failed snapshot once.

The Appearance tab owns a `TableAppearancePreview` with the shared semantic renderer and a fixed local sample. It updates display attributes immediately and releases its component on tab redisplay or hide. It has no Vault reads, editing handlers, or source-write path.
