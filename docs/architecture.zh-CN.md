# Structural Tables — 架构

<!-- section: boundaries -->
## 边界

`src/core` 是无宿主依赖的纯 TypeScript；配置、渲染、编辑器、阅读视图与应用接线分层。公共仓库不依赖其他仓库或本地 Vault。

<!-- section: parser -->
## 解析

解析器扫描分隔单元格包含一个或多个连字符的 GFM 候选分隔行，跳过带 BOM 且由 `---` 或 `...` 结束的 frontmatter、围栏代码和缩进代码，识别转义管道与代码跨度，输出源码范围、角色网格、合并锚点和诊断。

行列排序使用菜单移动与拖放共享的纯轴排列操作；先拒绝不完整跨度选区与角色变化，再验证结果的归属网格。添加行列与当前单元格草稿组合成一份候选源码和一次宿主事务。DOM 拖动控制器只管理选择手势、测量边界、反馈和取消，源码校验与写入仍由共享操作路径负责。

<!-- section: validation -->
## 验证

合并只向左或向上解析，因此不会形成方向环。验证再检查锚点、角色边界和矩形闭包；结构模式启用后执行严格列数检查。

<!-- section: rendering -->
## 渲染

一个共享 DOM 渲染器被阅读视图后处理器和 CodeMirror 呈现组件调用。实时预览把语义块组件和独立的源码抑制装饰保存在 CodeMirror `StateField` 中，由独立的视图插件管理输入法组合输入、原生源码焦点和视图生命周期。Markdown 范围始终作为 CodeMirror 文档中的权威源码保留；源码抑制装饰只控制其视觉/宿主原生渲染，本身并不是语义表格。结构表格始终进入该路径；普通 GFM 仅在启用可选接管设置时进入。设置刷新会重建编辑器装饰和阅读视图，但不改变源码。每个可见锚点单元格按行列跨度携带块末端与行内末端标记，CSS 依照真实网格位置而非 DOM 子元素位置移除内边框；交替行底色位于透明数据单元格下方，可穿过跨行单元格。插件接管的表格组件增加单元格选区、行列把手、每组一个的游动 Tab 停靠点和聚焦的文本编辑框。可视单元格焦点会映射到对应 Markdown 锚点并同步 CodeMirror 逻辑选区，同时显式保留呈现所有权；**编辑表格源码**则反向交接所有权，显示原始源码行、滚动到映射单元格并聚焦 CodeMirror。鼠标指针由插件接管拖动选区；触摸指针使用两次点选的范围状态，并刻意保留宿主对首次指针事件的处理，以支持滚动和长按。阅读视图先在 Obsidian 提供的完整 section 文本上保留 Markdown 容器和保护区上下文进行解析，其中包括围栏/缩进代码、frontmatter、注释、展示公式，以及由 `pre`、`script`、`style`、`textarea` 开始的字面量 raw HTML 区块；再把解析结果筛选到报告的源码起止行，最后映射原生表格或行表头语法产生的精确源码块。这样既不会接管受保护示例，也能避免后面的表格被前面的结构表格替换；递归渲染回调会被忽略。单元格内容交给 Obsidian MarkdownRenderer，组件生命周期负责清理。

实时预览把不可变的 CodeMirror 组件描述与 DOM 持有的交互会话分开。源码编辑所有权与浏览器焦点分开管理：打开外部控件时保留原始源码和选区，视觉单元格操作才显式交接所有权并同步逻辑光标。源码位置或表格索引改变时，内容未变的表格会重新绑定当前快照，保留原编辑框及草稿。解析结果缓存在编辑器状态中，只有文档改变才重新解析；选区、设置及输入法状态变化只重建装饰。单元格遍历归属纯核心，按源码顺序双向访问可见锚点，跳过合并覆盖位置。

阅读视图替换、独立导出暂存和原生渲染比较的根节点直接通过目标的 `ownerDocument` 创建；实时预览比较使用编辑器的文档。接纳另一个窗口创建的根节点只会改变文档，不会更换原来的 DOM 原型，宿主辅助方法因此可能继续使用错误窗口的构造器创建子节点。插件拥有的表格节点沿用目标根节点的辅助方法。原生 Markdown 内容仍由宿主负责，插入后可能保留不同的构造器，因此匹配不要求所有原生后代都与插件属于同一 realm。


缺少 section 信息的独立 Markdown 渲染通过单独的源码校验适配器处理：读取已保存的笔记，对比完整原生渲染区块（包含普通表格以排除字面标记的歧义），复核源码身份和生命周期，并在语义单元格渲染完成后返回。不会按 DOM 序号猜测表格身份，也不修改 Markdown。失败、过期、不完整或有歧义的匹配保留原生结果。

原生 Callout 区块使用源码拥有的挂载会话，不依赖 DOM 反向位置或未经核对的表格序号。编辑器通过 CodeMirror 的正向位置映射定位源码区块；两种视图都核对原生渲染的区块特征，包括富文本原始段落和由多个区块组成的表头。只有完整匹配的目标数量一致时，相同表格才按源码顺序对应。嵌入笔记中的目标和有歧义的映射保持不变。编辑器挂载按源码范围和精确内容跟踪变更，待恢复的单元格焦点只在对应替换挂载后兑现。宿主 DOM 变化会重试待处理映射；诊断区分 DOM 缺失、渲染中、渲染失败、未匹配、歧义和已挂载状态。

Callout 写入通过可逆效果将焦点目标保存在 CodeMirror 自身的历史记录中，与相邻正文编辑分开。撤销和重做在重新挂载后恢复精确源码和路径对应的目标，也涵盖在单元格之外调用的命令。不记入历史的源码变化由宿主历史映射目标位置，不维护另一套撤销栈。

有未保存输入的编辑器在 DOM 销毁前，将文字交给应用会话级恢复缓冲。恢复窗口支持复制和显式放弃；关闭窗口后仍可通过命令找回。恢复流程不会自动把过期草稿写入新表格。

<!-- section: editing -->
## 编辑

命令和原位编辑先在纯内存所有权网格中产生候选源码，再重新解析验证。行列变换会重建矩形合并所有权并迁移仍存在的锚点。guarded 操作拒绝无效边界以及未预期的未选中或隐藏内容丢失；明确的清空或删除意图只允许移除用户已选的可见 owner；单元格输入先转义代码跨度外尚未转义的管道，再通过一次 CodeMirror 整表事务提交。每次显式写入源码都会按终端显示宽度（包括中文与 emoji）对齐分隔管道，同时保持行表头分隔符、对齐记号、转义管道、Wiki 链接、代码跨度和原有 LF、CRLF 或 CR 换行符；渲染路径不调用序列化器，也不写入源码。

<!-- section: interchange -->
## 互操作

纯核心投影把有效结构表格展开为稳定的列路径和二维数据。GFM、TSV、CSV 与后续记录迁移共用该投影；语义 HTML 直接使用验证后的 rowspan、colspan、角色、scope 和真正的换行元素。整篇笔记的 HTML 导入接线把 HTML DOM 归一化成单元格、跨度、th/td 角色和规范 `<br>` 视觉换行，再交给纯核心生成并重新解析结构 Markdown。Sheets Extended 迁移只接受唯一、非边缘且整列严格为 `-` 的伪分隔列。

接管网格范围使用独立的规范化 v1 载荷，只含相对 canonical owner ID 和 raw owner token。粘贴只接受尺寸与 owner 拓扑一致的这种载荷，构造并验证一份完整候选，再通过一次源码事务提交。菜单的剪贴板写入和读取分别检查平台能力。无法识别的载荷、普通文字和 HTML 不会从接管网格选区回退到隐藏源码。范围 HTML 用转义后的原始文字表示内容并携带跨度；普通 Markdown 将第一条复制行作为表头，并在可表示时保留结构标记，不保证外部 GFM 仍能保留合并拓扑。

整表 PNG 导出使用独立桌面会话，在保留来源 cssclass 和 Callout 作用域的离屏容器中以正常语义渲染器渲染经过验证的模型，等待单元格、公共 `finishRenderMath()` 完成屏障、字体和图片后测量完整内容，再通过固定版本、MIT 授权的 `html-to-image` 将带样式 DOM 克隆经 SVG foreignObject 和 canvas 转为图片。已加载的图片附件在本地光栅化，所需 SVG symbol、包含伪元素的实际 CSS 资源与成功选择的字体来源会嵌入；字体收集遵循来源优先级，保留笔记已有字体回退，不修改宿主样式表。资源校验解析属性和声明，不扫描文字。主题保护观察来源实际外观及主题模式，允许无关的渲染器 head 更新，以及同一已验证笔记内的 render child 替换。该路径不复用刻意简化的 Word/HTML 投影。取消、渲染失败、源码或主题改变、尺寸/节点/资源超限、无法截取的动态嵌入均拒绝结果。最终 PNG Blob 同时供预览、剪贴板和 Vault 附件保存使用；重复请求取消前一个会话，关闭弹窗或卸载插件会释放渲染组件、离屏 DOM、事件订阅和 object URL，不写源码，也不上传内容。

<!-- section: base-promotion -->
## Base 提升

纯核心从共享表格投影生成稳定且唯一的 Property key、记录值、文件名候选、列表型 `structural-tables` 成员资格和嵌入式 Base 源码。新提升保留所有去除首尾空白后的非空列路径作为 Property key，只有整列空表头使用 `column_n`；规范化重名或控制字段冲突通过数字后缀解决，显示配置使用经过 YAML 引号处理的 `note.<key>` 属性标识，过滤表达式使用方括号访问。Metadata 读取器解析 YAML，兼容属性标识与旧版表达式形式的列顺序，不重写笔记。列表头合并被展平为列路径，行表头合并值按记录重复；数据区域合并必须先拆分。应用层为每次提升分配独立的表格目录和 ID，先创建全部记录与 `_promotion.json`，再重新解析未变化的源表并执行一次编辑器替换。记录不使用插件身份属性。创建、快照或编辑器操作失败时保留全部已生成产物，并报告目录路径和原始错误。Vault API 无法原子地核对文件内容并回收目录，因此失败处理不自动清理产物。

带版本的 `structural-tables` YAML 配置保存表 ID 和清单路径，在原生 Base 保存后继续保留；旧 metadata 注释继续兼容。无标记 Base 只有在一个必需成员条件唯一定位代码块时才成为恢复候选，任何写入前必须用原始清单核对源笔记、表 ID 和原清单路径。已经移动的无标记宿主不能安全推断，需要显式修复 metadata。重复 ID、冲突 metadata、无效 YAML 和不安全路径均拒绝处理。离线 YAML 解析器固定版本并打包为浏览器运行代码。

恢复清单记录原表、生成 Base、源文件和初始记录路径。恢复只替换当前匹配 ID 的插件 Base，不删除记录。成员资格不查询路径，因此记录重命名或移动无需事件监听。插件的新建记录命令根据当前宿主笔记目录计算收件箱；宿主移动不触碰已有记录。运行时同时读取 `structural-tables` 和旧版 `structural_table_ids`；双字段等价时接受，无效或冲突时停止处理。显式的全库迁移逐文件预览计划动作，并让可选清理数量随开关同步；执行时复核插件拥有的 frontmatter 与完全匹配的 Base 代码块，更新使用 LF、CRLF 或 CR 换行的旧成员字段与 Base 过滤条件，并提供默认关闭且只作用于有效成员笔记的 `structural_record_id` 清理。围栏感知扫描会忽略更长 Markdown 围栏内的示例；后续写入失败时只反向恢复迁移写入的属性和代码块，保留无关并发编辑。

<!-- section: settings -->
## 设置

持久化设置使用 schema 1 envelope。此前的无版本对象是唯一旧格式：启动时只规范化一次并排队写入 schema 1 envelope；当前 schema 1 数据不会重复迁移。任何显式未知或畸形 schema 都进入不兼容只读状态，当前插件版本绝不覆盖未来字段。设置保存统一经过一个串行协调器；每个排队任务持有不可变快照，失败保持可见且可重试，卸载时等待队列并对最后一个失败快照再重试一次。
