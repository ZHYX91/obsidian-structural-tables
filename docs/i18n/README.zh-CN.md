# Structural Tables

[English](../../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [Deutsch](README.de.md) · [Español](README.es.md) · [العربية](README.ar.md) · [Français](README.fr.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [한국어](README.ko.md) · [Tiếng Việt](README.vi.md)

Structural Tables 在普通 Markdown 管道表格上增加合并单元格、多行列标题、行标题和无列标题表格。Markdown 仍然保持可读，仅仅查看表格不会改写笔记。

表格可以放在引用、Callout 和列表续行中；编辑或格式化后仍会留在原来的位置。只有在转换为 Obsidian Base 前，才需要先把嵌套表格移到顶层。

## 功能

- 在单元格中写 `<`，可与源顺序中的前一列合并；写 `^`，可与上一行合并。
- 支持多行列标题、用 `||` 把源顺序中的前几列标为行标题，以及完全没有列标题的表格。
- 在阅读视图和实时预览中显示相同的合并结构。
- 可将整张表格的行列互换，标题和合并单元格随之转换。如需重置列对齐，或普通 Markdown 表格需要改用 Structural Tables 语法，会先提示确认。
- 在实时预览中直接编辑单元格，并可增删、移动、对齐行列，合并或拆分选区，以及在不删除文字的情况下改变标题角色。
- 从浏览器、Excel 和 Google Sheets 粘贴受支持的 HTML 表格，并保留跨行、跨列结构。
- 将表格复制为 HTML、普通 GFM、TSV 或 CSV。
- 在桌面端预览完整表格 PNG，并复制图片或保存为 Vault 附件。
- 可选让 Structural Tables 编辑普通 GFM 表格；关闭该设置后立即恢复 Obsidian 原来的表格界面，Markdown 不会因此改变。
- 将表格转换为 Obsidian Base，并在确认前查看生成的记录笔记和属性映射。记录移动或重命名后仍会继续出现在原来的 Base 中。
- 拒绝会意外丢失未选中内容或隐藏源码的写入；用户明确清空或删除可见选区时允许移除所选内容。结构语法有误时保持原样并显示诊断，而不是静默改写笔记。

<!-- section: requirements-and-compatibility -->
## 要求与兼容性

Structural Tables 要求 Obsidian 1.12.7 或更高版本，支持桌面版 Obsidian 和 Android。将表格转换为 Base 还需要启用 Obsidian 核心插件 Bases。

在 Structural Table 中，严格匹配的 `<`、`^` 和分隔行里的 `||` 有特殊含义。如果检测到其他已启用的表格插件也使用这些记号，Structural Tables 会提示一次可能的冲突。

启用**阅读视图渲染**后，使用 Obsidian Markdown 渲染器的图片导出工具也可以呈现合并表格。导出前请先保存笔记，并检查导出预览。如果导出片段无法与已保存的源码唯一对应，插件会保留原样，不猜测合并关系。

在 Obsidian 1.13.7 中，部分启用 FakeLink 的桌面插件组合可能让新打开的独立窗口在阅读视图中显示空白。先切回 Obsidian 主窗口一次，再返回独立窗口，笔记可能就能完成渲染。若仍为空白，可在主窗口阅读，或使用实时预览。

若要使用 Advanced Tables 等插件的源码命令，右键单元格并选择**编辑表格源码**。打开工具栏或对话框时，源码选区会保持原位。Tab/Enter 的行为由 Advanced Tables 自行决定；需要时请切换到 Obsidian 的源码模式。使用第三方排序或行列移动后，请检查单元格内容及合并关系：语法有效并不代表原意未变。无效的结构语法会保持可见并显示诊断；Structural Tables 不会静默修复或撤销其他插件的修改。

<!-- section: installation -->
## 安装

可从 Obsidian 第三方插件目录安装 Structural Tables：打开**设置 → 第三方插件 → 浏览**，搜索 **Structural Tables**，点击**安装**，然后启用插件。

如需手动安装，请从[最新版本](https://github.com/ZHYX91/obsidian-structural-tables/releases/latest)下载 `structural-tables-<version>.zip`，解压到 `Vault/.obsidian/plugins/`。压缩包包含 `structural-tables/` 目录及其中的 `main.js`、`manifest.json` 和 `styles.css`。重新加载 Obsidian，再在第三方插件中启用 Structural Tables。

<!-- section: usage -->
## 用法

**快速上手：** 先创建 Markdown 表格；在要合并的单元格里输入 `<`（与源顺序中的前一列合并）或 `^`（与上一行合并）；在实时预览中将源码光标移出表格，或者切换到阅读视图查看效果。需要修改内容时，点击实时预览中的单元格即可。

1. 先创建或粘贴一张普通 Markdown 管道表格。
2. 在单元格中写 `<` 可与源顺序中的前一列单元格合并，写 `^` 可与上方单元格合并。
3. 在分隔行中放置一个相邻的 `||`，可把源码中位于它前面的列标记为行标题。
4. 在实时预览中把源码光标移出表格，或切换到阅读视图，即可查看渲染结果。若要再次编辑原始 Markdown，右键已渲染的单元格并选择**编辑表格源码**。
5. 在实时预览中点击单元格即可编辑文字。Enter 保存并前进，Escape 取消；其他快捷键和撤销规则见下方**高级编辑与安全删除**。
6. 通过表格边缘的 **+**、行列把手和右键菜单，添加、移动、合并、拆分或删除表格内容。Delete/Backspace 只清空所选文字，不会直接删除表格结构。
7. 将受支持的 HTML 表格直接粘贴到 Markdown 编辑器中即可导入。格式化、复制和 Sheets Extended 迁移从命令面板执行；转换为 Base 可从命令面板或表格右键菜单执行。

阅读视图只负责显示；原位编辑和表格控件位于实时预览中。

### 高级编辑与安全删除

单击单元格即可编辑。加粗、斜体、行内代码、emoji 和链接显示文字只有在能唯一对应原始 Markdown 时，光标才会定位到点击处；其余情况光标折叠到末尾，不再默认选中整格导致误覆盖。普通点击链接仍会打开链接，按 Alt 单击可修改显示文字。Enter 保存并移至下一行（末行会追加），Shift+Enter 换行，Tab 访问下一可见单元格；Up/Down 只在可证明的首／末视觉行跨格，并尽量保留水平光标位置。Cmd/Ctrl+B、Cmd/Ctrl+I 可切换草稿的粗体和斜体；键入、IME、粘贴及格式操作在保存前使用草稿本地撤销／重做。其他格式命令请使用**编辑表格源码**。

选中表格网格后，Shift+方向键可调整选区；Delete/Backspace 只清空所选单元格的内容，不删除行、列、表头类型或合并关系。确实要移除结构时，请右键选择**删除所选行**、**删除所选列**或**删除表格**，不必先清空文字。清空和明确删除都可一步撤销。

单击行或列把手可选择，第一次按住拖动就能直接移动。按住 Shift 点击或触屏依次轻点其他把手可扩选；拖动已选把手会整体移动。合并闭包和标题／数据区边界仍受保护。

### 表格语法

一张结构表格可以同时使用多行列标题和行标题：

```markdown
| 地区 | 销售额 | <   |
| 季度 | Q1     | Q2  |
| ---  || ---   | --- |
| 华北 | 10     | 12  |
| ^    | 8      | 11  |
```

分隔行正上方连续的表格行会作为列标题。`||` 不会增加列数，只是把源码中位于它前面的列标记为行标题。

表格遵循笔记的文字方向。在从右向左的笔记中，源顺序中的第一列和行标题显示在右侧。切换插件语言，或只在某个单元格输入阿拉伯语，不会倒转列顺序，也不会改变 `<`、`^` 和 `||` 的含义。

分隔行也可以直接放在第一行，这样表格就没有列标题：

```markdown
| --- | --- |
| Alice | 10 |
| Bob   | 20 |
```

选中完整的列标题区域后选择**取消列标题**，文字会保留，只是这些行改为普通数据。以后也可以重新选中表格顶部的连续行，把它们设为列标题。

合并标记必须形成一个完整矩形，并且不能跨越标题区和数据区。若要在单元格中显示字面量 `<` 或 `^`，请写成 `\<` 或 `\^`。

### 转置表格

先保存或取消正在编辑的单元格，再右键表格，选择**转置整张表格（行列互换）**；也可以把源码光标放在表格内，从命令面板运行该命令。无论选中了哪些单元格，转置都会作用于整张表。

转置后，行变成列，行标题与列标题互换，合并单元格也随表格转向。如果需要重置不同列的对齐设置，或普通 Markdown 表格需要改用 Structural Tables 语法来保留标题，会先弹出确认。取消不会改动表格。确认后，一次撤销即可恢复整张表；转置前后输入的文字分别保留在其他撤销步骤中。

如果转置会把相邻的管道分隔文字并入表格，命令会保留笔记原文。请在表格前后各加一行空行，再重试。

### 编辑、换行和公式

Shift+Enter、单元格右键菜单和多行粘贴都可以插入视觉换行。普通文字保存时使用统一的 `<br>`；如果原文已经手写成 `<br>`、`<br/>` 或 `<br />`，仅格式化表格时会保留原来的写法。

可以安全保存的单行 TeX 公式会原样保留。像 `$|x|$`、`$P(A|B)$` 这样的裸竖线在 Markdown 表格里有歧义，因此插件不会擅自保存，而是保留草稿。对于这两种简单情况，单元格菜单可以明确改写成 `\lvert … \rvert` 或 `\mid`；更复杂的公式需要手动修改。

### 普通 GFM 表格

普通 Markdown 表格默认仍使用 Obsidian 自带的编辑界面。开启**接管普通 Markdown 表格**后，也可以使用 Structural Tables 的实时预览控件；关闭设置即可立即恢复 Obsidian 原来的界面。

数据行可以比表头少列或多列；缺少的单元格会显示为空。如果某个数据行比表头多列，Obsidian 会隐藏多出的单元格。为保护这些隐藏文字，Structural Tables 会继续显示表格，但阻止编辑命令。请选**编辑表格源码**，把多出的文字移到可见列，或为表头补足列数，使这些内容能够显示。关闭普通表格接管时，Delete/Backspace 和表格删除继续使用 Obsidian 自带的行为。

### 粘贴和复制

在笔记的 Markdown 编辑器中粘贴时，开启**保留粘贴 HTML 表格的合并结构**后，可以转换受支持的多列 HTML 表格，并保留跨行、跨列和视觉换行。无法安全转换的 HTML 会交还 Obsidian 处理；只有在明确安全时，才会使用剪贴板中的完整纯文本版本。

如果文本需要保留空格、制表符、换行或标题段落边界，插件会使用完整纯文本版本。文字会保留，但表格布局或富文本格式可能丢失。如果没有安全的替代内容，插件会阻止这次粘贴，并保留当前选区。

只有正文 `td` 的 HTML 表格会保持无列标题，不会擅自把第一行当作标题。来源中真正存在的 `thead`/`th` 会按其语义导入。

先选中单元格，选择**复制所选单元格**或**剪切所选单元格**。粘贴时既可选中与载荷合并布局一致的目标矩形，也可只选一个未合并的目标单元格作为左上角锚点；后者可向右、向下扩表。只覆盖目标矩形内的内容，不删除其他合并单元格的范围外部分；角色、既有对齐、未选中的 Markdown 原文保持不变，无法安全表达的合并及隐藏源码会拒绝。复制不改笔记；剪切只在剪贴板写入成功且上下文未变化后清空。成功粘贴为一次可撤销的事务。

范围菜单的复制/剪切依赖平台的剪贴板写入能力，菜单粘贴则单独依赖读取能力；其中一项可用，不代表另一项也可用。普通文字、普通 HTML 或无法识别的范围数据不能直接粘贴到网格选区，也不会落到隐藏的 Markdown 源码。粘贴普通文字时，请打开单个单元格进行编辑；导入 HTML 表格时，请在笔记的 Markdown 编辑器中粘贴。也可以通过**编辑表格源码**直接编辑 Markdown。

在移动端，范围复制/剪切会写入纯文本 Markdown 表格，并检查系统剪贴板是否包含完全相同的文字；检查成功后，剪切才会清空内容。插件在当前会话中记住所复制的合并布局。只要剪贴板仍与本次复制一致，就可以粘贴到网格；剪贴板被其他内容替换，或重启 Obsidian／插件后，就不能再使用这次复制的合并布局。其他地方复制的文字，请粘贴到单元格编辑框或笔记编辑器。

供其他应用使用时，范围复制还会提供 HTML 和普通 Markdown。范围 HTML 表示单元格跨度，其中的 Markdown 作为原始文字显示。普通 Markdown 将第一条复制行作为表头，并在可表示时保留结构标记；它不保证其他应用仍能保持相同的合并布局，包括纵向合并。

要粘贴到 Word 等应用，可使用**复制整张表格用于 Word / HTML**或**将当前表格复制为 HTML**。也可以复制为普通 GFM、TSV 或 CSV。由于 GFM 本身要求存在标题行，把无列标题表格转换成普通 GFM 时会加入一行空标题作为兼容处理。

复制的 HTML 会记录每个数据单元格对应哪些标题。Word 保存 DOCX 时可能丢弃这些关联，即使表格看起来仍然正确。因此，包含多列行标题的表格可能无法完整保留这些标题对应关系。

在移动端或富格式剪贴板不可用时，HTML 复制命令会复制以制表符分隔的纯文本，并提示标题结构与合并单元格已展平。单元格内部的换行和制表符会变成空格；这种降级形式不含富文本 HTML 格式和合并单元格结构。

### 导出表格图片

在桌面端，右键表格选择**导出整张表格为图片…**，或将源码光标放在表格内，从命令面板运行**导出整张表格为图片**。预览显示最终 PNG，**复制图片**与**保存 PNG 到 Vault**使用同一张图片；复制需要剪贴板权限，保存按 Vault 配置创建新的附件，避开重名文件，不插入笔记链接。普通 GFM 表格也可通过原生菜单或命令面板导出。

快照使用当前主题、背景、表格样式和密度，包含完整表格、合并表头、已渲染文字、受支持的公式与已加载本地图片附件，不含编辑控件或选框。长内容会扩展图片，不会裁切。请先保存或取消正在编辑的单元格草稿；导出不包含该草稿，也不会修改 Markdown。生成期间源码、主题或表格方向改变时，需要重新导出；已完成的预览保留原快照。

图片采用固定 2 倍缩放，限制为单边 8192 像素或 1600 万像素。如果表格太大、必要内容无法加载，或交互内容／笔记嵌入无法截取，导出会提示失败，不生成不完整的 PNG。笔记已使用替代字体时，图片会保留当前显示的字体。跨域图片可能受浏览器安全策略限制，请使用本地附件。导出在本地完成，没有上传服务。移动端暂不提供图片导出，请使用文本复制命令。

### 转换为 Base

转换前请先保存笔记；如果表格位于引用、Callout 或列表中，请先把它移到顶层。预览会显示目标文件夹、准备生成的记录笔记、属性名称，以及哪些表格结构会在转换时展开。

新记录默认创建在 `<原笔记所在文件夹>/_structural-table-records/<table-id>/`。这里仅是默认创建位置：之后移动或重命名记录笔记，并不会让它离开原来的 Base。`structural-tables` 列表属性负责保存这种关联。

如果转换在创建了一部分文件后失败，插件会保留这些文件并报告所在文件夹，方便检查处理。**从当前 Base 恢复原表格**会从 `_promotion.json` 恢复转换前的表格快照，但不会删除已经生成的记录笔记。

空标题会使用 `column_n`；非空标题（包括纯数字和带前导零的名称）会尽量直接作为属性名。重名或保留名称会追加数字后缀。

### 恢复被中断的编辑

单元格修改被拒绝时，编辑框会尽量保持打开。如果外部修改或视图重建打断了尚未保存的草稿，Structural Tables 会在当前会话中保留一份恢复副本。使用**恢复被中断的单元格草稿**可以重新打开恢复窗口。Obsidian 或插件重启后这些副本会消失，因此重要内容应先复制出来。

<!-- section: settings -->
## 设置

设置页分为**常规**、**视图**和**外观**三个页签。

语言可选**跟随 Obsidian**，或 English、简体中文、繁體中文、日本語、Deutsch、Español、العربية。自动模式使用 Obsidian 的语言；不支持时显示英文。切换插件语言只改变控件和提示，不会翻译笔记或改变表格方向。

- **常规**：语言、HTML 表格粘贴转换和插件冲突提示。
- **视图**：阅读视图、实时预览、诊断，以及默认关闭的**接管普通 Markdown 表格**。
- **外观**：跟随主题、网格表或三线表；表格宽度和位置；舒适或紧凑间距；可选的交替行底色。

**跟随主题**把边框、表头颜色和字重交给当前 Obsidian 主题，没有列标题的表格也遵循主题的外框样式。**网格表**会为列标题和行标题使用一致的轻度标题底色，并用略粗的单实线标明完整列标题区域的下边界，以及 `||` 声明的行标题分界。尚未添加数据行时，这两种分界也会保留。分界线沿合并单元格边缘绘制；没有表头时保持均匀网格。**三线表**只保留顶线、底线和列标题区域下方的一条横线，不增加正文竖线；没有列标题时自然只剩顶线和底线。

外观设置只影响显示，不会修改 Markdown。

**导出 Word 文档：** 本插件用扩展 Markdown 语法保存合并单元格和复杂表头。需要转换 DOCX 时，可以使用 [DocWen Assistant](https://github.com/ZHYX91/obsidian-docwen-assistant) 搭配另行安装的本机 DocWen，并在 DocWen 的 Markdown 语法设置中开启 **Structural Tables 输入扩展**；如果还需要从 Word 转回结构化 Markdown，则开启相应的输出扩展。转换功能是可选的，仅适用于支持的桌面系统。

<!-- section: limitations -->
## 局限

Structural Tables 不是电子表格计算引擎，不会计算公式。它也不支持每个单元格单独设置样式、表格标题和编号、单元格内的块级 Markdown，或真正的多行 Markdown 单元格。

导入 HTML 时，单元格内容会转换为纯文本和受支持的 `<br>` 视觉换行，不会把复杂富文本自动翻译成 Markdown。转换为 Base 时，表格布局会变成普通属性：多行列标题用 ` / ` 连接，行标题变成普通属性，合并的行标题值会写入它覆盖的各条记录。数据区存在合并单元格时，必须先拆分后才能转换。

从 Base 恢复表格需要生成的 `_promotion.json` 仍位于 Base 代码块记录的路径。

<!-- section: privacy-and-security -->
## 隐私与安全

Structural Tables 在本地处理表格，不上传内容，也不收集分析数据。单元格内容仍由 Obsidian 渲染，因此笔记中的远程图片或嵌入内容会继续遵循 Obsidian 自己的网络行为。图片导出可能读取当前主题的字体或装饰资源，并将其嵌入本地 PNG；离线导出需要这些资源在本地可用。

仅仅查看表格不会修改 Markdown。编辑和菜单命令都需要用户主动触发，并会在替换源码前检查结果。转换为 Base 只会创建预览中列出的本地文件；如果中途失败，已经创建的文件会保留下来供检查，而不会自动删除。
