# Structural Tables — 产品需求

<!-- section: purpose -->
## 目标

让用户只用可读的 Markdown 管道表格表达合并单元格、多行列表头和行表头，并在 Obsidian 中获得可靠渲染与安全编辑。

<!-- section: syntax -->
## 语法契约

严格匹配的 `<` 向左合并，`^` 向上合并，`\<` 与 `\^` 表示字面量。每个分隔单元格都遵循 GFM，至少包含三个连字符。分隔行之前连续且等宽的行均为列表头。分隔行内部最多一个无空格 `||`，其左侧为行表头列，且 `||` 不计入列数。

<!-- section: validity -->
## 有效性

结构表格所有行必须严格等宽。合并必须落到单一左上角内容锚点、形成完整矩形、不得越界，也不得跨越角表头、列表头、行表头和数据区域。无效时保留源码，不猜测、不自动修复。

<!-- section: capabilities -->
## 功能范围

桌面端与 Android 的阅读视图、实时预览渲染；普通 GFM 默认使用原生表格，并可选择无损、可逆且不改 Markdown 的接管模式；带表格安全 Wiki 链接管道转义和输入法保护的原位单元格编辑；鼠标拖动选区、游动式键盘导航，以及触屏依次点选首格和末格形成矩形选区，焦点或编辑器光标离开后清除插件选区；不推移表格对齐、且在粗指针设备上保持可见和触摸尺寸的覆盖式行列把手；跟随主题的列表头/左上角表头背景和更浅的行表头背景；细指针内容驱动行高、粗指针触摸高度下限和跨度感知边框；插入、安全删除、移动、对齐、格式化、向左/向上合并、矩形选区合并、拆分、设置表头和整篇检查；接入 Obsidian 普通表格的原生选区与右键菜单；保留 rowspan/colspan 的 HTML 表格粘贴；语义 HTML、普通 GFM、TSV 与 CSV 输出；Sheets Extended 分隔列迁移与冲突提示；普通表格和结构表格均可右键升级为 Base；预览明确展示非空数字/文本表头路径原样成为 Property、空表头使用 `column_n`、多行/合并列表头展平、行表头转为属性，并在写入任何文件前阻止数据区合并单元格；路径无关的 `structural-tables` 列表成员资格且不使用记录自身的插件 ID、恢复清单、保留记录的原表恢复、按宿主当前目录创建后续记录，以及带预览的显式旧属性迁移；原生双语设置；明确诊断。格式化必须先预览规范源码并由用户确认，确认前不改 Markdown；其他结构编辑也均为显式操作，普通渲染不改源码。

<!-- section: exclusions -->
## 非目标

插件不包含公式、样式、块级/真正的多行内容、标题编号、重复表头源码属性，也不把导入 HTML 单元格中的富文本自动转换为 Markdown。严格匹配的 `<br>`、`<br/>` 与 `<br />` 仍是普通单元格文本，Obsidian 会把它们渲染为视觉换行；插件只原样保留，不把它们建模为特殊语义，也不自动统一写法。Base 提升不猜测数据区域合并的记录语义，不接管 Bases 原生 New 按钮，也不在恢复时删除生成或后来移动的记录笔记。

<!-- section: success -->
## 验收标准

纯核心测试覆盖正例、反例和规范序列化；产物可复现且离线；真实 Obsidian 验收与自动化结论分开记录。每个移动端候选都需要当前 Android 模拟器证据；Android 真机和 iOS 不在验收范围内。
