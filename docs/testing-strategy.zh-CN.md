# Structural Tables — 测试策略

<!-- section: levels -->
## 层级

测试分为五层，上一层通过不能替代下一层：

1. **纯核心单元测试**：解析、序列化、表格操作、Base 转换等不依赖 Obsidian 的逻辑。
2. **DOM 测试**：渲染、选区、样式和剪贴板行为。
3. **插件接线测试**：命令、设置、编辑器和 Reading View 的模块连接。
4. **打包与发布检查**：生产 bundle、版本、固定依赖和发布运输。
5. **真实 Obsidian 验收**：最低支持版本和当前版本中的真实界面、输入法、主题和移动端行为。

Reading View 的回归必须使用完整笔记文本和真实源码行范围，确保一张表不会误占用同一笔记里的另一张表。

独立窗口的 DOM 回归使用彼此独立的 jsdom realm，并让宿主辅助方法绑定其创建文档。同时检查 `ownerDocument` 和插件拥有的容器、表格、单元格容器的构造器；仅接纳节点不能让测试通过。原生 Markdown 后代可以保留宿主的构造器，但前后正文、单元格内容和合并结构必须完整。覆盖原生 section、Callout、延迟区块映射、独立导出和原生渲染比较。

DOM 模拟器适合验证结构和多数 CSS 规则，但不能替代真实 Obsidian 中的几何、滚动、主题变量和触摸行为。

<!-- section: parser-cases -->
## 解析用例

至少覆盖：

- 普通 GFM 默认不由插件接管，开启设置后可由插件显示和编辑；
- GFM 分隔单元格使用一个或多个连字符，以及左/中/右对齐写法；
- GFM 数据行少列时补空显示，多出的源码单元格保留且禁止有损写入；
- 无列标题表格、单数据行表格、多行列标题和行标题；
- `<` / `^` 合并、转义后的字面量记号和 `||` 行标题分隔；
- 转义管道、代码跨度、代码块、frontmatter、注释、raw HTML 和数学块；
- LF、CRLF、CR 三种换行和精确源码范围。

<!-- section: invalid-cases -->
## 反例

反例需要同时验证“诊断正确”和“源码没有被改写”。重点包括：

- 合并标记缺少锚点；
- 合并区域不是完整矩形；
- 合并跨越标题区和数据区；
- `||` 位于边缘、出现多次或两根管道之间带空格；
- Structural Table 行宽与分隔行不一致；
- 会切穿现有合并区域的标题角色变化；
- 受保护 Markdown 区域中的伪表格不能被识别。

<!-- section: commands -->
## 命令与编辑

核心操作测试覆盖：

- 单元格编辑、合并、拆分；
- 插入、删除、移动和对齐行列；
- 设置或取消列标题、设置或取消行标题；
- 删除或移动合并锚点时保持内容；
- guarded 或隐式操作若会丢失未选中或隐藏内容、或切开合并区域必须拒绝；用户明确清空/删除已选内容则作为获授权的破坏性意图单独测试；
- Wiki 链接和嵌入中的管道只转义一次；
- Shift+Enter、菜单和多行粘贴统一写入可表示的 `<br>`；
- 格式化结果重新解析后语义一致，并保留 LF/CRLF/CR。

序列化测试还要覆盖 ASCII、中文、组合字符和 emoji 的显示宽度。Live Preview 的 DOM 测试覆盖焦点、Tab/Shift+Tab、输入法组合态、把手、选区清理以及撤销/重做。

<!-- section: interchange -->
## 粘贴与互操作

需要覆盖：

- 多行列标题路径和合并值展开；
- HTML 的 `thead`、`th`、`td`、`rowspan`、`colspan`、`scope` 和换行；
- 只有正文 `td` 的 HTML 表格保持无列标题，不擅自把第一行变成标题；
- CSV 引号、TSV 清理和普通 GFM 兼容输出；
- Sheets Extended 唯一分隔列及反例；
- Wiki 链接、字面量管道和单元格内换行；
- 接管网格范围的复制/剪切/粘贴：覆盖 1x1、单列、全空和完整合并 owner，验证 exact-topology raw 往返、剪贴板失败/过期 session 拒绝、菜单读写能力分别不可用，以及拒绝普通文字或 HTML 且绝不回退到隐藏源码；
- 范围 HTML 携带跨度并将原始 Markdown 转义为文字；普通 Markdown 将第一条复制行作为表头，不承诺外部 GFM 保持相同合并布局；
- 整篇笔记的 HTML 导入路径将混合正文、多表、图片、附件、链接、MathML/SVG 等不安全载荷交还 Obsidian 原生粘贴；
- GFM 替换确认前重新解析当前源码，并拒绝过期预览。
- 整篇笔记的 HTML 导入路径对标题、继承的保留空白和保留换行使用完整纯文本回退；缺少安全替代时不替换原选区。

<!-- section: base-promotion -->
## Base 转换

纯核心测试分成几组：

- **属性名称**：数字、前导零、空白、Unicode、保留名、重名，以及 emoji、空格、点号、引号和反斜杠。
- **无列标题**：生成 `column_n` 属性，并确保第一条数据不会被当作标题丢失。
- **结构展开**：多行/合并列标题、行标题、合并行标题和数据区合并阻断。
- **文件名**：Windows 保留设备名、重复文件名和安全字符处理。
- **归属与恢复**：新旧成员属性、恢复清单、无标记 Base 的严格证明、冲突和歧义拒绝。
- **换行与围栏**：LF/CRLF/CR、反引号/波浪线围栏，以及更长围栏中的示例排除。

内存 Vault 事务测试还要证明：阻断方案零写入；记录、清单或源码替换失败时不会误删并发内容；恢复不会删除记录；宿主笔记移动后新建记录使用新的默认位置；缺失或不匹配的清单必须拒绝。

旧属性迁移需要覆盖预览、默认关闭的旧 ID 清理、并发变更检测、三种换行，以及失败回滚只恢复插件拥有的更改。

<!-- section: host -->
## Obsidian 实机验收

在明确命名的临时 Vault 中，至少测试最低支持版本和当前稳定版。按改动范围选择场景；涉及渲染、输入或样式时，应覆盖 Default 和 Minimal 的亮色/暗色代表组合。

重点检查：

- Reading View 与 Live Preview 的表格归属、Callout、引用和列表续行；
- 无列标题、多行列标题、行标题、合并和普通 GFM 接管；
- 单元格编辑、输入法、Tab、撤销/重做和被拒绝草稿；
- 行列把手、拖动、触摸选区、焦点和横向滚动；
- 跟随主题、网格表、三线表、紧凑/舒适密度和不同宽度布局；
- HTML/GFM/TSV/CSV 粘贴复制和 Sheets Extended 迁移；
- Base 预览、确认、失败保留、记录移动/重命名、恢复和旧属性迁移；
- 插件关闭或卸载后不留下编辑器状态。
- FakeLink 与 Hover Editor 联用，分别检查普通表格接管开关、临时分离与重开，以及不重复挂载的编辑和历史操作；
- 独立整篇与选表导出，覆盖同貌 HTML、行内代码、延迟内容、新会话取代旧会话，以及渲染组件清理 DOM；
- 源码交接后执行 Advanced Tables 操作，保留精确光标或选区，并对操作后无效的结构提供诊断；
- 原生菜单共存、行列选区保留、单元格重新挂载和弹出窗口关闭。
- 冷启动后在桌面独立窗口打开阅读视图，包括启用 FakeLink 的组合。切换焦点前记录初始结果，再检查切回主窗口并返回后能否恢复正文；恢复成功不能把初次空白记为无条件通过。

截图和 DOM 测试可以辅助说明，但不能当作真实 Obsidian 验收结果。

<!-- section: mobile -->
## 移动端

选择 Android 回归时，记录 AVD、Android/API 版本、Obsidian 版本和精确候选身份。至少覆盖：

- 启动、Reading View 和 Live Preview；
- 双击编辑；
- 两点矩形选区与独立长按菜单；
- 触摸尺寸的行列把手；
- 表格内横向滚动；
- 中英文输入法组合输入；
- 关键编辑后的源码和撤销/重做。

Android 真机和 iOS 不在当前正式验收范围内，除非另行安排。
