# Structural Tables — 交互规范

<!-- section: principles -->
## 原则

源码始终可见、可恢复；渲染负责理解而非改写；可能丢失内容的操作必须拒绝。

<!-- section: live-preview -->
## 实时预览

CodeMirror 光标和选区均位于表格外时显示语义表格。渲染组件内，桌面端单击单元格、触屏上双击单元格或按 Enter/F2 可打开单行原位编辑器；桌面端拖动及带修饰键的操作仍用于选择，链接保持可点击。编辑框不会撑宽原列，只使用已选单元格的一层外侧焦点边框，不再显示内层文本框边框或缩放把手。Enter 提交，Escape 取消，Tab 提交并前往下一格。粘贴时会立即转义代码跨度外尚未转义的表格管道，且不重复转义。输入法合成期间不提交，也不切换渲染。

<!-- section: reading-view -->
## 阅读视图

用 `thead`、`tbody`、`th`、`td`、`rowspan`、`colspan` 与合适的 `scope` 渲染。单元格内部继续使用 Obsidian Markdown 渲染。

<!-- section: commands -->
## 命令

插入模板、格式化、向左合并、向上合并、拆分、检查、复制 HTML/GFM/TSV/CSV、预览并展开为普通 GFM、迁移 Sheets Extended 分隔列，以及迁移旧版 Structural Tables Base 属性均可从命令面板调用。格式化与展开为 GFM 都必须先显示可滚动、可选择的结果预览，确认时重新校验源表未变化，确认前不改源码。非空单元格合并时显示说明并保持原文。

<!-- section: interchange -->
## 粘贴与互操作

“保留粘贴 HTML 表格的合并结构”启用时，仅在剪贴板包含可验证的多列表格时接管粘贴；否则保留 Obsidian 原行为。thead 或连续 th 行成为列表头，表体最左侧连续 th 列成为行表头，rowspan/colspan 转换为规范的 `^`/`<`。单元格导入为纯文本，HTML 换行和块边界统一转换为规范 `<br>` 视觉换行。普通 GFM、TSV 和 CSV 输出会重复合并值，并用 ` / ` 连接多行列表头路径；HTML 输出保留语义角色、跨度、scope 与换行元素。

<!-- section: base-promotion -->
## 升级为 Base

右键普通表格显示“升级为 Base…”，插件接管的结构表格显示“展开结构并升级为 Base…”。操作无需选中整张表，只在已保存笔记内的有效表格上工作，并要求启用 Bases 核心插件。预览显示目标文件夹、记录数量、显示列名到稳定 Property key 的映射、生成的 Base 源码和所有适用的展开规则：多行列表头路径用 ` / ` 连接，合并列表头展开到覆盖的 Property 路径，行表头转为普通 Property，合并行表头值写入每条记录。新提升会把去除首尾空白后的非空表头路径（包括纯数字和带前导零的名称）保留为 Property key，并在生成的 Base 中统一使用方括号引用；只有整列空表头使用 `column_n`，规范化后重名或碰到保留 key 时追加数字后缀。已有提升 Base 和记录只兼容读取，不自动迁移。数据区合并单元格会以行、列和跨度标出并禁用确认，执行层在创建任何文件前再次检查阻断项。有效操作执行期间按钮禁用；创建失败显示原因、保持原表并把本次目录移入废纸篓。

生成 Base 的 metadata 注释保存稳定 table ID 与恢复清单路径。把光标放在该 Base 上，可使用插件命令按宿主当前目录创建空白记录，或预览并恢复原表。恢复明确说明生成记录会保留。记录移动、重命名和整理不显示提示，也不改变成员资格。

旧属性迁移只在用户显式执行命令后扫描 Vault。弹窗逐文件列出计划变更，以及成员笔记、已提升 Base 代码块和旧记录 ID 的数量；旧记录 ID 清理默认关闭，切换后会立即同步本次移除数量和逐文件动作，且只作用于具有有效、非空 Structural Tables 成员属性的笔记。确认后先检查全部文件和插件拥有的 frontmatter 值是否过期，并在重写 Base 前再次核对源码，再把 `structural_table_ids` 替换为 `structural-tables`、更新使用 LF、CRLF 或 CR 换行的旧 Base 过滤条件，同时保留无关 Property 与笔记正文。后续文件写入失败时，只反向恢复迁移拥有的 Property 和完全匹配的 Base 代码块，使并发发生的无关编辑得以保留；Base 扫描会忽略包在更长 Markdown 围栏内的示例。新旧成员值无效或冲突时，在允许确认前停止。

<!-- section: table-selection -->
## 表格选区与右键菜单

默认情况下，普通 GFM 表格沿用 Obsidian 原生 Markdown 表格的单元格选区、整行/整列把手和共享事件菜单，可直接创建第一项结构语法。启用“接管普通 Markdown 表格”后，光标不在表内的普通 GFM 表格使用与结构表格相同的插件控件、把手、原位编辑、完整编辑菜单、布局、密度和交替行底色，且不改变源码；关闭设置会立即刷新已打开视图并恢复原生行为。鼠标可拖过多个单元格；触屏依次点选首格和末格形成矩形选区，首次指针事件不被插件拦截，以保留横向滚动和长按菜单。普通表格和插件接管的结构表格都会在右键菜单提供相应的 Base 升级入口，无需选中整张表。细指针设备上，指针移到单元格时仅显示对应行、列的把手，键盘聚焦或已选中的把手保持可见；粗指针设备的把手始终显示且至少为 44 个 CSS 像素。把手绝对覆盖在表格外侧留白中，并按表格真实矩形定位，因此适应内容靠左、居中和适应窗格三种布局都不会被把手推移。单元格获得焦点时不得让桌面端全部把手同时出现；焦点或 CodeMirror 选区离开当前表格、或指针进入另一张插件表格时，当前插件选区必须清除。单元格组、行把手组和列把手组各只提供一个 Tab 停靠点；方向键与 Home/End 在当前组内移动焦点，横向移动遵循 RTL 方向，焦点始终有清晰轮廓。舒适和紧凑密度在合并前后保持稳定的单元格最小尺寸，粗指针设备保留触摸高度下限。单元格编辑框打开时，Shift+Enter 和右键菜单“在单元格中插入换行”都会插入规范 `<br>`，粘贴多行纯文本也会以同样方式规范化。显式编辑与表格操作会按中文及 emoji 的显示宽度对齐整张源码表格，同时保持 `||`、对齐记号、转义管道、Wiki 链接、代码跨度和 LF/CRLF/CR；仅显示的渲染绝不写入。继续保留已有的原生风格整列选中效果。矩形多单元格选区提供“合并所选单元格”；单个合并单元格提供“拆分合并单元格”。除左上角外存在内容、选区跨角色边界或只包含已有合并区域的一部分时，拒绝合并并保留源码。

从表格顶部开始的完整行选区可以设置列标题行；从最左侧开始且覆盖所有表格行的完整列选区可以设置或取消行标题列。插件接管的表格菜单还可插入、安全删除、移动和对齐所选行列：在合并区域内部插入会扩展该区域；删除锚点但合并区域仍存在时会迁移内容；任何会丢弃非空内容、拆散合并矩形或跨越表头边界的操作都会被拒绝。接管关闭时，普通表格继续使用 Obsidian 原生菜单和把手行为。

<!-- section: diagnostics -->
## 诊断

无效结构显示红色边缘和可读原因；不替换阅读视图中的原表格，也不在编辑器中隐藏源码。

<!-- section: settings -->
## 设置

使用 Obsidian 原生设置控件和顶部分页，分为“常规”“视图”“外观”。活动页签同时使用强调色下划线和半粗字重，页签基线与内容面板之间保留稳定间距。设置保存失败必须持续可见并提供明确的“重试”操作；遇到显式不兼容 schema 时持续显示警告并禁用控件，同时保留三个页签的导航。语言、HTML 表格粘贴转换和启动冲突提示位于第一个“常规”页，自动语言显示为“跟随 Obsidian”并附带说明。“视图”提供默认关闭的“接管普通 Markdown 表格”，说明必须明确源码保持标准、关闭后恢复原生表格，并提示可能与其他表格插件冲突。新安装默认使用“适应内容宽度—靠左”，“外观”也提供“适应内容宽度—居中”和“适应窗格宽度”。已渲染的列表头与左上角表头使用较强的主题派生背景，行表头使用较浅背景，交替行仅作用于数据单元格。布局只改变整个表格的位置和宽度，不改变单元格内容对齐。控件标签与说明支持英文和简体中文。
