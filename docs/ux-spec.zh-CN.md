# Structural Tables — 交互规范

<!-- section: principles -->
## 原则

源码始终可见、可恢复；渲染负责理解而非改写；会意外丢失未选中或隐藏内容的操作必须拒绝。用户明确清空或删除可见选区时允许移除所选内容；其他编辑操作继续检查是否会意外丢失内容。

<!-- section: live-preview -->
## 实时预览

有效结构表格由语义块组件负责呈现，但 Markdown 始终作为 CodeMirror 文档中的权威源码保留。当原生 CodeMirror 源码界面持有焦点且选区与表格相交时，显示原始 Markdown 供直接编辑；打开外部控件时保留源码编辑状态及其精确选区。可视单元格交互只同步逻辑源码位置，不会退出呈现模式；**编辑表格源码**会显式把焦点和映射后的单元格位置交还 CodeMirror。

### 单元格编辑

- 桌面单击、触屏双击及 Enter/F2 可打开编辑框。若呈现文本节点在原始 Markdown 中能唯一定位，则按 UTF-16 偏移放置折叠光标，涵盖粗体、斜体、行内代码、链接显示文字和 emoji；HTML 实体仅在可证明的解码边界定位。文字重复、渲染改写等歧义直接把光标放到草稿末尾，不再整格全选以免误覆盖。普通链接单击仍按链接激活；按 Alt 单击链接可进入显示文字编辑。键盘入口可选择完整草稿。
- 编辑框覆盖在原单元格上，不应改变列宽，也不应再出现第二层输入框边框。编辑态不叠加网格范围选中的整块底色，主题原有的表头、斑马纹、背景和边框继续可见。
- Enter 提交并打开下一逻辑行的同一列；在末行时，本次编辑和追加新行属于同一个宿主事务。Escape 取消；Shift+Enter 插入草稿换行。
- Tab/Shift+Tab 按源顺序访问可见锚点并跳过合并占位。左右键只在能证明安全的折叠水平边界跨格；混合或 RTL 文字交给原生光标行为。上下键仅在真实几何证明光标位于首／末视觉行时跨格，并尽量保持目标首／末视觉行的水平位置；软折行内部、几何不可测、文字选区和 IME 均不得抢键。
- textarea 持有编辑焦点时，Cmd/Ctrl+B 和 Cmd/Ctrl+I 只切换当前草稿选区的粗体/斜体，并保留另一种已有强调。普通输入、组合输入、粘贴、草稿换行以及这些格式操作统一进入草稿本地撤销/重做历史；继承自父 Scope 的主编辑器历史与格式命令不得在提交前改写已保存源码。其他格式化命令仍属于源码路径，需要先使用**编辑表格源码**。
- 提交被拒绝时保持完整草稿，不跳转、不追加新行。
- textarea 之外，未修饰的 Delete/Backspace 只清空当前网格选区代表的完整可见 owner 内容。清空绝不删除行、列、表头角色、对齐、合并拓扑或整张表；选区本来为空时不产生写入。
- 接管网格的右键菜单提供相同的清空意图，并明确提供“删除所选行”“删除所选列”“删除表格”。明确删除可以直接移除所选可见内容，不要求先清空；每次操作只形成一个可撤销的宿主事务。明确选择全部行或全部列时直接删除整张表，不构造零行或零列表格。
- Shift+方向键从原始逻辑 anchor/head 扩展或收缩网格范围，再复用合并 owner 闭包；不会把扩张后的 bounds 当作新的逻辑 head。textarea 内的文字选区快捷键仍只作用于文字。
- 普通 GFM 未开启接管时继续使用 Obsidian 原生 Delete 行为；开启接管后才采用上述清空/明确删除策略。存在隐藏 GFM 溢出源码单元格时保持只读，必须先在 Markdown 中处理这些额外单元格。
- 输入法组合期间不提前提交或抢占按键。

### 生命周期和焦点

从正在编辑的 A 单击 B，必须按真实 pointerdown→blur→pointerup→click 顺序，在同一次手势中保存 A 并打开 B，覆盖同表、跨表及 Callout。不能在 pointerdown 抢先聚焦 B：旧 textarea 的 blur 提交可能销毁 widget 和 click 目标。等待整次点击意图完成，再按最新源码／DOM 定位；草稿拒绝提交或仍在 IME 组合时保留原草稿并取消跳转。双击选词、文字拖选、Shift 网格选区与普通链接激活各归其位。

源码位置变化、其他段落编辑或表格索引变化时，只要目标表格本身未变，当前编辑会话和草稿应继续绑定到同一张表。外部修改使目标失效时，应停止写入并保留可恢复草稿。

撤销/重做后，尽量把焦点恢复到对应的可见单元格。Callout 中的表格也遵守同样规则，不应因为宿主重新渲染而把整段源码暴露出来。

刚打开且未修改的单元格，如果本地撤销和重做栈均为空，就把历史快捷键交回文档，避免打开 B 后无法撤销已提交的 A。存在待处理输入、组合输入、已修改草稿或本地重做分支时，历史仍由草稿持有。

在同一呈现单元格内按住拖动，把两个可证明的端点映射为草稿局部文字选区；跨入另一个单元格则转为网格选区。连续双击的第一次点击打开编辑框后，第二次点击仍按原呈现位置选词，不受 Markdown 标记引起的文字位移影响。

点击源码呈现表格下方的段落时，LTR 和 RTL 笔记都保留该表的横向位置。单元格内容未变时保留原表格；内容有改动时只提交一次，即使呈现表格需要重建，也只在这次精确替换的内容渲染完成后恢复横向位置。新的输入、滚动、源码变化、编辑器或方向变化会取消等待中的恢复。双击和长按等原生文字选择行为保持不变。

点击长表格上方或下方的正文、编辑器空白时，不要在原生指针处理函数确定落点的过程中插入草稿提交。从 CodeMirror 初始估高到单元格异步渲染完成，替换表格的高度应保持稳定，随后交还内容的自然尺寸。内容缩短时允许文档自然变矮，不保留人为高度，也不通过强制折叠选区掩盖指针冲突。

单元格草稿由浏览器根据当前原始文字自动决定方向，并继承单元格对齐，包括显式的左对齐、居中和右对齐。草稿中可见的 Markdown 链接地址等语法可能影响方向，即使呈现后的单元格隐藏了这些文字。插件语言与笔记／表格方向保持独立。外部控件取得焦点时结束旧的指针意图；之后新发起的源码点击，在焦点返回时仍保留自己的意图。临时高度只属于原来的呈现表格，渲染完成时即清除，包括表格暂时断开连接的情况。

### 普通 GFM 表格

默认使用 Obsidian 原生表格界面。开启“接管普通 Markdown 表格”后，普通 GFM 表格使用与结构表格相同的渲染和编辑控件，但源码仍保持标准 GFM；关闭设置后立即恢复 Obsidian 原生界面。

## 命令

**插入结构表格**直接以可用模板替换编辑器选区，因此快速上手应先让用户把折叠光标放在空白行。

插入模板、格式化、向左合并、向上合并、拆分、检查、复制 HTML/GFM/TSV/CSV、预览并展开为普通 GFM、迁移 Sheets Extended 分隔列，以及迁移旧版 Structural Tables Base 属性均可从命令面板调用。格式化与展开为 GFM 都必须先显示可滚动、可选择的结果预览，确认时重新校验源表未变化，确认前不改源码。非空单元格合并时显示说明并保持原文。

普通 GFM 只有顶部一行表头。转换预览提供保持原有方向和转置，仅对只有行标题的输入推荐转置。结果面板渲染最终 GFM，并可切换到可选择的源码。复制使用同一份结果；编辑替换只提交一次，并隔离撤销步骤、重新核对完整源码及文件和视图身份。阅读预览只能复制。替换前列明合并单元格、表头层级、行标题作用、空兼容表头和对齐的变化。存在隐藏溢出时，可在说明遗漏内容后复制可见单元格，但禁止替换。

### 整表转置

右键中的行操作与列操作相邻，列对齐归入列操作，后面单独一组提供“转置整张表格（行列互换）”，再往后才是整表复制与导出。此操作始终作用于整张逻辑表格，与当前选区大小无关；命令面板和原生普通 GFM 表格菜单提供同一功能。单元格文本草稿仍在编辑时拒绝，不允许静默提交或丢失输入。行表头只使用现有的 `||` 分隔语法，不提供特殊标记列。

转置保留内容与合法合并单元格拓扑，列标题行数和行标题列数互换，横向与纵向跨度互换，原地单事务写入并与前后输入隔离，可撤销恢复原始源码与目标坐标。统一列对齐在新列上保留；原始列对齐不一致时才提示确认将新列统一重置为默认对齐。普通 GFM 转置后需要 `||` 等扩展语法时提示兼容性变化，即使列对齐统一也需确认；两类警告均不适用的转置直接执行。全部行都是列表头、转置后需要全部列都成为行表头等当前语法不可表达的结果，或存在无效、隐藏溢出源码时必须拒绝写入。菜单或确认框可以短暂清除视觉网格选区。确认期间重新校验所属编辑器／视图、文件／路径、目标内容和活动草稿，过期目标不写入。

提交前重新解析完整笔记，确认转置结果保留目标表格的起止位置及行列互换后的单元格关系。如果相邻的管道分隔文字会被并入结果，保留笔记原文，并提示在表格前后添加空行。在原 document 中打开的确认框，不能在所属编辑器移入另一窗口后继续写入。

## 粘贴与互操作

在笔记编辑器的 HTML 导入路径中，启用“保留粘贴 HTML 表格的合并结构”后，可验证的多列表格会转换为结构表格。

若剪贴板只有一张其余内容安全、但要么完全为空、要么只包含当前导入器无法忠实保留的文本语义（`pre`、`sup`、`sub`）的表格，则在存在非空纯文本版本时原样粘贴完整纯文本，不推断 TSV、Markdown 或 TeX 等价表示；若这种已知有损载荷没有纯文本版本，则阻止该次粘贴并保留当前选区。

混合正文、多表、图片、HTML `embed`、附件、链接、MathML/SVG、表格本身或外围携带的富语义、剪贴板文件以及非文本 MIME 载荷仍交给 Obsidian 原生粘贴，不会一律降级为纯文本。

普通 `div`/`span` 包装和额外的 `text/*` MIME 表示本身不会禁用这一窄范围纯文本回退。

thead 或连续 th 行成为列表头，表体最左侧连续 th 列成为行表头，rowspan/colspan 转换为规范的 `^`/`<`。

单元格导入为纯文本，HTML 换行和块边界统一转换为规范 `<br>` 视觉换行。

接管网格的已选范围使用独立的有界剪贴板合同。复制保留原始 Markdown 和规范化合并 owner 拓扑；剪切仅在剪贴板成功且 source/path/editor/document/selection/session 未变时清空。粘贴到已选矩形仍要求尺寸与合并拓扑完全一致；只选一个未合并目标格时，复制的矩形以该格为左上锚点，必要时向右、向下扩表，原表头角色和原列对齐不变，新列使用默认对齐。目标矩形内部的非空值按明确粘贴意图覆盖；任何合并 owner 延伸到矩形外、跨表头角色无法表达、隐藏溢出或原始文本无损回写失败都必须整次拒绝。成功粘贴只形成一次可撤销的写入，选中粘贴后区域；外部文本／HTML 和过期载荷绝不进入隐藏源码。

菜单复制/剪切与菜单粘贴分别检查平台的剪贴板写入和读取能力，一项受支持不代表另一项也受支持。粘贴普通文字时，请进入单个单元格的编辑框。导入 HTML 表格时，请使用笔记编辑器；**编辑表格源码**则提供直接编辑 Markdown 的入口。

单击目标格已经会打开编辑框。向未修改的草稿粘贴插件多格载荷时，仍以该格为网格锚点，一次提交；已修改草稿或正在组合输入时拒绝范围粘贴，要求先完成或取消草稿。损坏的插件载荷不能降级为草稿文字。单格复制和普通文字仍按格内文字处理。

移动端范围菜单采用经核验的纯文本传输，以绕过可能仅支持图片的宿主富格式桥接。复制／剪切需读回完全相同的系统文字后才成功；本会话保存的 owner 拓扑还必须在异步读取期间保持复制身份、文档／文件／编辑器／源码及选区不变。粘贴同样支持匹配矩形或单格锚点扩展，但绝不单凭普通 GFM 推断合并拓扑；重启、替换系统剪贴板内容或读取失败均不得修改源码。

整表 HTML 复制命令绕过移动端仅支持图片的富格式桥接，在移动端或桌面富格式剪贴板不可用时使用完整的制表符分隔文本备选内容。TSV 投影将单元格内部的换行和制表符转为空格，保留行分隔符与列之间的制表符。两个入口均按实际写入形式提示；纯文本通知说明标题结构与合并单元格已展平，且不含富文本格式。剪贴板拒绝写入时提示失败。

范围复制还提供便于其他应用使用的 HTML 和普通 Markdown。范围 HTML 将每个 owner 的原始 Markdown 转义为文字并表示跨度，不把 Markdown 渲染成富文本。普通 Markdown 将第一条复制行作为表头，并在可表示时保留结构标记；它不保证外部 GFM 仍具有相同的合并拓扑，尤其是纵向合并。

普通 GFM、TSV 和 CSV 的整表输出会重复合并值，并用 ` / ` 连接多行列表头路径；HTML 输出保留语义角色、跨度与换行元素。简单标题使用行/列 `scope`。复杂标题使用文档内唯一的 `id`/`headers`，关联相交的每条行列标题路径，覆盖合并数据和交错标题跨度。角落标题只标注对应的行标题列，不关联所有数据单元格。每次整表复制使用新的 ID 命名空间，不添加缺乏实际分组的行列组 scope 或应用专属标记。

普通 GFM 保留代码跨度中实际显示的反斜杠和管道。由于 GitHub GFM 与 Obsidian 原生渲染对反引号内管道转义的处理不同，含管道的代码跨度使用带实体的内联 HTML `<code>` 元素；接收方须允许内联 HTML。其他代码跨度保留反引号写法。HTML 表格导入独立使用结构表格转义，闭合代码跨度不会增加仅为 GFM 所需的反斜杠。导入结果为普通 GFM 时，含管道的代码跨度使用实体编码的内联 HTML，使原生渲染和可选接管保留相同的列与文字。

HTML 转换仅接管一张完整且支持的表格。混合正文、多张表、标题、公式、图片、附件以及无法保留的链接交还笔记原生粘贴。在单元格编辑器中，不支持的 HTML 会使用完整纯文本版本并提示；没有纯文本时保留当前编辑内容。已确认的空单元格仍可清除选中文字。复制 HTML 时，公式、图片、附件及内部或相对链接回退为原始 Markdown/LaTeX，以保留引用，不直接嵌入任意 HTML。

安全的单行公式会原样保留，包括分数、上下标、`\lvert`/`\rvert`、`\lVert`/`\rVert`、`\mid`、已有 `\|` 范数和使用 TeX `\\` 的矩阵。`$|x|$`、`$P(A|B)$` 等裸竖线、公式内的实际换行、TeX 注释或逐字命令以及未闭合定界符，会在保存前被拒绝，完整草稿仍可编辑。请按符号含义使用明确的 TeX 命令；普通美元符号写为 `\$`。拒绝提交不会跳转单元格或追加行；被中断的草稿可在当前插件会话内恢复，但不保证重启后保留。格式化会保留既有公式源码，不猜测旧范数是否原本想写成绝对值。

桌面端整表图片导出可从源码命令面板、插件表格菜单和普通表格原生菜单调用。弹窗先生成完整主题和背景快照，再预览最终 PNG；复制图片和保存 PNG 到 Vault 共用同一份字节。不包含活动单元格草稿和编辑控件，不改 Markdown，已完成快照保持稳定；生成期间源码或主题变化时要求重试。剪贴板拒绝时仍可保存到 Vault；移动端明确提示仅桌面支持。固定 2 倍输出限制为单边 8192 像素和 1600 万像素；资源或渲染失败、超时以及交互或笔记嵌入均明确报错，不把裁切或内容缺失记为成功。

<!-- section: base-promotion -->
## 转换为 Base

右键普通表格显示“升级为 Base…”，结构表格显示“展开结构并升级为 Base…”。只有已保存笔记中的有效表格可以转换，并且必须启用 Bases 核心插件。

### 预览

确认前必须展示：

- 目标文件夹和记录数量；
- 显示列名到最终 Property key 的映射；
- 准备生成的 Base 源码；
- 多行列标题、合并列标题、行标题和合并行标题会如何展开；
- 数据区合并单元格等阻断问题；
- 与 `<br>` 等内容相关的显示差异；
- 准备生成的记录路径和 frontmatter。

如果存在需要用户判断的显示差异，确认按钮必须在用户明确接受后才可用。取消或关闭预览不能创建文件。

### Property 和记录

非空标题尽量直接作为 Property key；空标题使用 `column_n`。重名或保留名称追加数字后缀。记录通过 `structural-tables` 列表属性与 Base 关联，不依赖文件所在目录，也不需要插件专用记录 ID。

默认创建目录只是新记录的初始位置。用户之后移动或重命名记录，不应破坏 Base 成员关系。

### 写入和失败

执行前再次检查阻断项、源码身份和编辑器目标。记录和恢复清单创建完成后，只有在原表格仍未变化时才替换源码。

如果中途失败，保留已经创建的文件并报告目录，不自动清理可能已被用户或同步工具修改的内容。

### 恢复与旧版本迁移

从 Base 恢复表格时，使用 `_promotion.json` 中的原始快照，并保留已经生成的记录笔记。清单缺失、来源不匹配或归属无法唯一证明时拒绝恢复。

旧属性迁移只在用户主动执行命令后运行。预览逐文件列出更改；旧记录 ID 清理默认关闭。写入前重新检查源码和插件拥有的 frontmatter，失败回滚只恢复插件自己的改动，不覆盖无关的并发编辑。

## 表格选区与右键菜单

### 行列把手

- 鼠标设备悬停单元格时，只显示对应的行、列把手。
- 把手使用固定尺寸的装饰图标及原生表格把手主题色；显露、悬停、选中和键盘焦点有独立的视觉层次，拖拽保留选中状态与反馈。
- 图形与底色位于点击区内部，缩小视觉外轮廓不缩小既有按钮热区。图标不增加焦点停靠点，也不抢占按钮的指针事件。
- 键盘聚焦或已经选中的把手保持可见。
- 触屏把手保持可点击尺寸，不遮住前一段文字。
- 把手位于表格外侧，不应改变表格本身的水平对齐。
- 会裁剪内容的 Callout 为编辑把手预留紧凑、稳定的操作区；触屏保留较大的点击空间。阅读视图无需预留编辑操作区。
- 添加行控件位于滚动容器及其横向滚动条下方，并随容器尺寸更新位置。
- 单元格、行把手组和列把手组各只提供一个 Tab 停靠点；方向键在组内移动，横向方向遵循 RTL。

### 选择与拖动

鼠标可拖出矩形选区；触屏依次点选首格和末格形成矩形。完成后的触摸选区在区内长按时保持，不应被长按动作重新开始选择。

第一次按住行／列把手就可拖动当前新选的合并闭包；按下后直接松开则只选中。Shift 点击或触屏依次点选另一个把手扩选；再拖动已选把手可整体移动。不得拆分合并 owner 或跨标题／数据角色边界。目标非法不写源码，Escape、pointercancel、失焦、离开表格和源码替换安全取消；RTL、触摸和边缘持续滚动保持一致。

### 菜单操作

插件接管的实时预览菜单依次分组：所选单元格的复制/剪切/粘贴；可用的合并/拆分与表头角色；行；列（包含列对齐）；整表转置；整表 GFM 预览、Word/HTML 复制与 PNG 导出；源码与 Base；清空所选单元格；删除整表。整表输出入口相邻并共用一组。删除行和删除列分别留在各自组末尾；删除整表独立置于最后一组并保留警示样式。

只有所选列的对齐方式全部相同时，才勾选对应的列对齐项；混合对齐不勾选。表头角色菜单不显示设置为当前相同数量的表头行或列，符合条件的取消表头操作仍保留。打开菜单时冻结逻辑选区，执行前重新验证。

矩形多单元格选区可合并；单个合并单元格可拆分。除源顺序中的第一个单元格外存在非空内容、选区跨角色边界或只选中现有合并区域的一部分时，拒绝操作。

完整顶部行选区可以设置列标题。选中当前完整列标题区域时，可以**取消列标题**而保留文字；这与“删除行”是两种不同操作。源顺序中从第一列开始的完整列选区可以设置行标题。选中完整列时，**取消整张表格的行标题设置**会取消整张表的行标题角色，并保留所有单元格内容。

普通 GFM 在“接管普通 Markdown 表格”关闭时继续使用 Obsidian 原生菜单和把手，插件只贡献适用的菜单项。阅读视图提供简短的 GFM 预览与复制、整表 PNG 导出入口。

## 设置

设置页使用 Obsidian 原生控件，并分为“常规”“视图”“外观”三个页签。保存失败需要持续显示错误并提供“重试”；遇到无法读取的未来 schema 时，保留导航但禁用会覆盖设置的控件。

### 常规

- 语言：跟随 Obsidian、English、简体中文、繁體中文、日本語、한국어、Deutsch、Français、Español、Português (Brasil)、Русский、Tiếng Việt、العربية；
- 是否转换粘贴的 HTML 表格；
- 是否提示其他表格插件的语法冲突。

自动语言识别 Obsidian 的语言 ID，区分简体和繁体中文；不支持的宿主语言回退为英文。兼容已有的 `auto`、`en` 和 `zh-CN` 设置，语言选项使用各语言自己的名称。阿拉伯语设置页和对话框从右向左排列，其他支持的插件语言从左向右排列，与笔记方向分开。RTL 提示中的路径、数字和代码独立排版，源码预览保留源顺序。

表格继承笔记方向。源顺序中的前几列是行标题，显示在起始侧：LTR 在左侧，RTL 在右侧。插件语言和某个单元格的文字不会重排列或改变 `<`、`^`、`||` 的含义。左右菜单操作和网格方向键遵循表格方向，显式左／右对齐仍指屏幕上的左右。双向文本无法可靠判断视觉边缘时，草稿左右键保留浏览器原生行为，仍可用 Tab 和 Shift+Tab 切换单元格。

### 视图

- Reading View；
- Live Preview；
- 无效结构诊断；
- 默认关闭的“接管普通 Markdown 表格”。

接管设置的说明必须明确：Markdown 仍是普通 GFM，关闭后恢复 Obsidian 原生表格，并可能与其他表格插件发生冲突。

### 外观

新安装默认跟随主题。样式、布局和密度彼此独立：

- **跟随主题**：边框、表头颜色和字重由当前 Obsidian 主题决定；没有列标题或仅有行标题的表格，其顶部外框也遵循主题设置；
- **网格表**：列标题、行标题和交叉标题使用同一套轻度标题底色与字重；完整列标题区域的下边界，以及 `||` 声明的行标题分界使用略粗的单实线；这两种结构分界在仅有表头时也保留，分界线沿合并单元格边缘绘制；没有表头时保持均匀网格；
- **三线表**：只画顶线、底线和列标题区域下方的横线，行标题不额外增加竖线或背景；
- 无列标题三线表只保留顶线和底线；
- 用户显式设置的列对齐优先于行标题默认对齐。

“线条与底色”集中样式和交替行底色，“布局与间距”集中布局与密度。下方不可编辑的合并示例使用真实表格渲染器，立即反映四个控件。说明示例不读取或编辑笔记，而设置会保存并作用于全库。

布局只改变整张表格的位置和宽度；外观设置不修改 Markdown。
